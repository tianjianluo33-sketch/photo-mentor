# AI 摄影导师

一个面向摄影初学者与爱好者的网站雏形，提供两个同级入口：**互动学习**与**现场拍摄指导**。用户可以直接使用现场指导，也可以先练习，再自愿把学习目标带入实拍。

当前版本用于体验和验证产品流程。现场建议使用预设的教学示例，尚未连接真实图像分析服务。

## 当前功能

| 模块 | 可以体验的内容 |
| --- | --- |
| 互动学习 | 曝光与运动、景深、构图三节模拟练习；调整控件后查看示意变化与规则反馈 |
| 独立现场指导 | 直接进入，选择目标、设备、反馈深度和现场限制，查看对应的示例方案 |
| 风格参考 | 查看教学方法卡，将目标带入练习或现场指导 |
| 重拍对比 | 查看示例前后变化；选择个人照片进行本机视觉对比，并记录自己的偏好 |
| 练习记录 | 查看本机保存的提交与提示使用情况；练习达标不会被表述成已掌握 |
| 页面导航 | 使用 URL hash 路由，可在静态托管与仓库子路径下访问 |

**个人图片不会自动获得 AI 点评。** 示例建议仅对应内置场景；真实照片的上传分析、连续取景指导和云端同步还未接入。

## 本地运行

推荐使用 **Node.js 24 LTS** 与 npm。项目最低 Node.js 版本为 **22.12**；CI 使用 Node.js 24。

```sh
npm install
npm run dev
```

在终端显示的本地地址打开网站。开发服务器仅用于本地开发。

```sh
# 运行规则与行为测试
npm test

# 类型检查与生产构建
npm run build

# 本地检查生产构建
npm run preview
```

首次安装后会生成或读取 `package-lock.json`。CI 和需要与锁文件完全一致的安装应使用 `npm ci`。

## 数据去向

- 课程操作、内置场景和示例反馈在浏览器内运行，无需模型密钥。
- 用户选择的个人图片只供当前页面本机预览和对比，不发送给应用服务端或模型供应商，也不作为练习记录持久保存。
- 练习记录与对比判断保存在当前浏览器的本机存储中，供同一浏览器恢复。它们不会在不同设备之间同步；清除浏览器网站数据会删除这些记录。
- 网站没有接入账号、支付、统计追踪或真实 AI 服务。加载部署后的网页及其静态资源，仍会向托管服务发起普通网页请求。

## 模拟与真实拍摄的边界

模拟画面用于说明参数或构图变化。它不是相机传感器、镜头光学或图像处理算法的完整复现，也不能据此保证现实拍摄结果。

本版本中的现场方案是明确标注的教学示例。个人图片不会套用示例结论；前后对比允许用户保留原图偏好。课程完成、使用提示、练习达标与独立掌握是不同状态。

## 后续接入真实 AI

接口与结构约定见 [开发与验收](./开发与验收.md)。建议按以下顺序扩展：

1. 建立服务端会话和图像上传服务，校验文件类型、大小、图像尺寸与必要元数据。
2. 在服务端调用模型，按约定返回图像 ID、目标版本、可见依据、最多两项动作与无法判断的条件。
3. 前端区分上传、分析、失败、重试和完成状态，避免旧请求结果覆盖新照片或新目标。
4. 让重拍对比引用明确的前后图像与目标，保留用户选择；通过真实场景测试建议是否可执行。
5. 为图像保存、删除、成本限制与会话访问控制设置明确规则，再开放外部试用。

模型密钥应保留在服务端，不能放进 React 源码、公开仓库或 `VITE_*` 变量。`VITE_*` 会进入前端构建产物，不适合保存密钥。

## GitHub 与静态部署

本仓库附带的 CI 只执行安装、测试和构建，**不会自动发布网站**，也不需要 Secrets。GitHub 仓库状态、测试结果和部署状态分别记录在 [实施状态](./docs/IMPLEMENTATION_STATUS.md)，以实际执行结果为准。

网站使用 hash 导航与 `base: './'`。因此，构建产物可部署在域名根路径或 GitHub Pages 的仓库子路径，无需为每个页面配置服务端重写。

如需发布到 GitHub Pages：

1. 在本地或独立部署流程中运行 `npm ci`、`npm test` 和 `npm run build`。
2. 将 `dist/` 的内容作为静态站点发布目录；不要将整个源码仓库作为构建产物。
3. 在仓库 **Settings → Pages** 中选择所采用的发布方式。可使用单独的 GitHub Actions 部署流程上传 `dist/`，或将构建产物放在专门发布分支的根目录。
4. 发布后检查首页、两个核心入口、刷新后的 hash 页面、图片选择和窄屏布局，再记录实际地址与验证结果。
